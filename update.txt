# 🚀 MASTER DEVELOPMENT PROMPT

# Build "Aero" — A Production-Grade Modern Node.js Web Framework

You are a **Senior Node.js / TypeScript Framework Architect and Core Runtime Engineer**.

Your task is to design and build a complete production-quality web framework called **Aero** from scratch.

Do not treat this as a demo project or tutorial.

Build it as a **real reusable framework/library** with clean architecture, strict TypeScript types, predictable APIs, comprehensive tests, documentation, performance-conscious implementation, and future extensibility.

---

# 1. PROJECT IDENTITY

**Framework Name:** Aero

**Purpose:**

Aero is a minimal, fast, type-safe and elegant Node.js web framework designed for:

* REST APIs
* Web applications
* Backend services
* SaaS applications
* Business applications
* ERP systems
* Microservices
* Internal enterprise APIs

### Design Philosophy

Combine the best architectural ideas from:

* Express — simplicity
* Koa — middleware composition
* Fastify — lifecycle hooks, schema-oriented architecture and performance
* Modern TypeScript — strong type safety
* Node.js native APIs — minimal dependencies

Do NOT copy source code from existing frameworks.

Study their architectural concepts only and implement Aero independently.

# 6. ARCHITECTURAL LAYERS

Aero must be internally organized around these layers:

```text
                    ┌─────────────────────┐
                    │     Application     │
                    └──────────┬──────────┘
                               │
                    ┌──────────▼──────────┐
                    │    Lifecycle        │
                    │      Hooks          │
                    └──────────┬──────────┘
                               │
                    ┌──────────▼──────────┐
                    │      Router         │
                    └──────────┬──────────┘
                               │
                    ┌──────────▼──────────┐
                    │    Middleware       │
                    └──────────┬──────────┘
                               │
                    ┌──────────▼──────────┐
                    │       Handler       │
                    └──────────┬──────────┘
                               │
                    ┌──────────▼──────────┐
                    │     Response        │
                    └─────────────────────┘
```

Keep responsibilities separated.

Do not put routing logic inside response handling.

Do not put body parsing inside the router.

Do not put plugin management inside the request object.

# 7. REQUEST LIFECYCLE

The request lifecycle MUST follow this logical order:

```text
Incoming HTTP Request
        ↓
Create AeroContext
        ↓
onRequest hooks
        ↓
Route Matching
        ↓
Populate route params
        ↓
Body Parsing
        ↓
preParsing hooks
        ↓
preValidation hooks
        ↓
Schema Validation
        ↓
preHandler hooks
        ↓
Global Middleware
        ↓
Route Middleware
        ↓
Route Handler
        ↓
preSerialization hooks
        ↓
Serialize Response
        ↓
onSend hooks
        ↓
Send HTTP Response
        ↓
onResponse hooks
```

Error at any stage:

```text
             ↓
        Error Handler
             ↓
      onError hooks
             ↓
      HTTP Error Response
```

IMPORTANT:

Route matching MUST happen before parameter validation because:

```text
/users/:id
```

must populate:

```typescript
ctx.params.id
```

before validating route parameters.

# 13. MIDDLEWARE

Implement Koa-style onion middleware.

Types:

```typescript
type NextFunction = () => Promise<void>;

type Middleware =
    (
        ctx: AeroContext,
        next: NextFunction
    ) => void | Promise<void>;
```

Example:

```typescript
app.use(async (ctx, next) => {
    console.log("before");

    await next();

    console.log("after");
});
```

Execution order:

```text
A before
B before
handler
B after
A after
```

Guard against:

```typescript
await next();
await next();
```

Calling `next()` twice must produce an error.

Synchronous exceptions must be converted into rejected promises.
